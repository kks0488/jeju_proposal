# 물량산출·다른 에이전트의 검증 규칙

> **현재 적용:** 사양 선택·견적은 [주택 지정사양 R1](TENDER.md)을 따른다. 아래 물량 검증 절차는 원본 도면/수량을 검증하는 후속 작업이며, R1 견적을 다시 사양 미정으로 되돌리는 조건이 아니다.

**현재 결과는 문자·목록표·기기표 1차 검토입니다. 전체 CAD 물량산출 엔진을 완성하거나 정확도를 검증한 상태가 아닙니다.** 이후 자동화는 아래 순서를 따릅니다.

## 기준 데이터와 상태

원본은 파일 해시로 식별합니다. `source-manifest.json`의 수신일은 발행일이 아닙니다. `evidence.json`의 `A:1AA` 같은 ID는 **해당 소스의 변환 DXF 객체 handle**이며 수정된 다른 파일에서 같은 ID를 무조건 재사용하지 않습니다. 근거 레코드의 `visual_verified:false`와 `approved:false`를 임의로 올리지 않습니다.

`drawings.json`은 목록 행 또는 본문 번호 후보입니다. 블록 정의, 실제 INSERT 배치, 도면 목록 행, 실물 기구 수량은 서로 다른 층위입니다. 블록 정의에 나타난 2~7층 같은 참고 텍스트를 실제 프로젝트 층수로 쓰지 않습니다.

## 다음 분석의 순서

1. **발행본 고정:** RFI-001/002/004/020에 따라 용도·도면목록·개정·좌표 기준·구조 조건을 확인합니다. PDF와 DWG를 같은 소스로 묶습니다.
2. **시트 분리와 축척 검증:** 모델공간 타일의 유효 도곽·설계/참고 영역을 식별합니다. 알려진 치수 2개 이상으로 구간별 축척·치수값·실제 길이를 대조하고 상세도 확대/삽입 스케일을 구분합니다. 단위 헤더만으로 측정하지 않습니다.
3. **실·부재·창호·장비 ID 부여:** 닫힌 경계가 없으면 자동 면적이 확정됐다고 하지 않습니다. 창호 일람과 평면 번호, 기기표와 배치 기호를 서로 대조합니다. 중첩/동적 블록·속성·MLeader·XREF·언더레이·설명문 등 현재 추출기의 비지원 범위를 확인합니다.
4. **기하 계산:** 길이/면적/체적은 검증된 코드로 계산하고 AI가 숫자를 눈대중으로 발주 수량에 넣지 않습니다. 중복선/반복 도면/가려진 객체/취소 도면을 제외합니다. 입면·단면·상세·마감표를 함께 사용합니다.
5. **측정 규칙 적용:** 철근 정착·이음·가공, 벽 양면/겹수/개구부, 지붕 실제 경사면, 배관 수직부/부속, 마감 재단손실 등을 공통 규칙으로 분리합니다. 발주수량과 순시공수량을 혼합하지 않습니다.
6. **독립 대조와 승인:** 수작업 또는 별도 산출 경로의 대표 표본·합계 검산을 수행하고 불일치는 원인까지 기록합니다. 허용오차는 공종/설계자가 승인하며 임의 정확도 99% 같은 수치를 주장하지 않습니다. 최종 물량은 적산 담당/설계자 검토 후 발행합니다.

## 수량 레코드에 필요한 필드

`quantity_id / 공통항목ID / 도면번호·개정 / 원본sha256 / 객체handle 또는 PDF쪽·영역 / 실·부재ID / 순수량 / 단위 / 산출식 / 길이·높이·두께 입력 근거 / 공제 / 겹수·면수 / 손실/할증 근거 / 발주수량 / 검증방법 / 검토자 / 승인일 / 미해결RFI`

판독 불가·상충·설계 미정은 숫자 0이 아니라 `null`로 둡니다. 표기 수량과 계산 수량은 별도 필드에 보존합니다.

## 에이전트별 역할 분리

| 작업 | 입력 | 출력 | 금지 |
|---|---|---|---|
| 원본/추출 담당 | 비공개 원본·PDF·변환 로그 | 인벤토리·근거 후보·변환 결손 목록 | 전체 원문 자동 공개 |
| 도서 정합성 담당 | 도면목록·근거·기존 요구 | RFI·변경 대조·시트 연결 | 도면 부재/오류를 제목 미검출만으로 확정 |
| 공종 적산 담당 | 승인 시트·측정 기준 | 근거 있는 수량 초안 | 미확정 사양/단위를 임의 채택 |
| 독립 검수 담당 | 수량·원본·산출 코드 | 중복/누락/단위/공제 검산 | 작성 결과를 검증 없이 승인 |
| 견적 비교 담당 | 승인 패키지·비공개 업체견적 | 범위·사양·가격 보정 비교 | 다른 조건 총액으로 최저가 결론 |

Codex와 Claude Code 중 어느 쪽이든 같은 데이터/규칙을 사용합니다. 두 모델이 같은 답을 냈다는 것만으로 독립 실측 검증이 되지는 않습니다.

## 재현 방법과 안전한 출력

```sh
python3 -m venv .local/jeju-analysis-venv
.local/jeju-analysis-venv/bin/pip install -r procurement/requirements.txt
# 원본을 덮어쓰지 않고 비공개 경로로 변환; 로그도 함께 보관
# dwg2dxf -o .local/cad/A.dxf /승인된_원본/건축.dwg
.local/jeju-analysis-venv/bin/python procurement/scripts/extract_dxf.py   --input .local/cad/A.dxf --source-id A --output .local/cad/A-inventory.json
.local/jeju-analysis-venv/bin/python procurement/scripts/build.py
python3 procurement/scripts/validate.py
```

추출 스크립트는 문자·기본객체 인벤토리 보조 도구입니다. 정식 시트 해석·벽/창호 수량·전체 도면 렌더링·법규 검증을 수행하지 않습니다. 공개할 근거는 사람이 제한사항과 개인정보를 검토한 후 `data/evidence.json`에 선별 반영합니다.

분석에 사용한 전체 텍스트/변환 로그의 작업 복사본은 해당 작업 컴퓨터의 저장소 `.local/cad-20261012/`에 비공개로 두었습니다. 다른 컴퓨터에는 자동으로 동기화되지 않습니다. 원본 DWG나 전체 DXF를 GitHub에 올리지 않습니다.
