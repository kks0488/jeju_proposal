# 표준 견적 회신 양식과 비교 규칙

**목표는 파일 형식 통일이 아니라 가격의 전제가 같은지 확인하는 것입니다.** 업체가 Excel/PDF로 제출하더라도 아래 필드와 항목ID를 유지하면 됩니다. 내부 정본은 읽기 쉬운 Markdown/JSON으로 관리하며, 작성된 실제 견적은 비공개 보관합니다.

## 1. 제출물 묶음

견적 표지와 요약, 공종별 상세내역, 수량 산출 근거, 제품/사양 목록, 제외·지급품·잠정·옵션·설계변경 목록, 공정표·배정팀·품질/검사·보증/하자 조건을 함께 받습니다. 서로 다른 문서의 총액과 포함 범위가 일치해야 합니다.

## 2. 표지 필드

공통 패키지/도면 발행번호·개정, 반영한 ADD-ID, 실제 계약 법인과 브랜드, 견적일·유효기간·공사기간·착공 전제, 수량 산출 방식, 통화, 부가세 처리, 지급조건, 현장소장·동시현장·협력 범위를 적습니다. 등록/보험/보증 증빙과 연락처는 비공개 첨부 참조로 둡니다.

## 3. 상세 행 형식

| 필드 | 작성 기준 |
|---|---|
| 항목ID·공종·품명 | [61개 공통 범위](SCOPE.md)의 ID 유지; 예: WIN-01-01처럼 하위행 확장 |
| 위치/창호/실/장비ID | 실제 위치가 확인돼야 중복/누락 대조 가능 |
| 규격·모델·시공법 | ‘고급형’, ‘동등 이상’만 적지 말고 제시 제품/성능과 기준 적합 여부 |
| 단위·수량·수량근거 | 도면번호/개정·산출식·공제·손실·작업위치 명시 |
| 단가 | 재료·노무·장비 단가 또는 근거가 있는 복합단가 |
| 금액 | 세전 금액; 수량×복합단가와 일치 |
| 상태 | 확정 단위견적 / 근거 있는 식견적 / 타행포함 / 제외 / 옵션 / 잠정 / 해당없음 |
| 포함·제외·이견 | 포함되는 다른 항목ID, 제외 이유, RFI/대안ID, 산출 이견을 명시 |

금액이 모르면 `null`/미견적입니다. **0은 실제 0원이지 미확인의 대체값이 아닙니다.** ‘타행포함’도 대상행 ID 없이 0원만 쓰지 않습니다. ‘식’은 상세를 생략할 권한이 아니며 그 아래 구성·수량·포함범위를 첨부합니다.

## 4. 합산과 중복 방지

재료·노무·장비로 나눴다면 `복합단가 = 재료단가 + 노무단가 + 장비단가`입니다. `단위견적 금액 = 수량 × 복합단가`입니다. 일괄 금액은 별도 상태와 구성 근거를 둡니다.

`기준안 세전총액 = 직접비 + 현장/공통관리비 + 법정경비 + 본사일반관리비 + 이윤 + 승인된 잠정금액`으로 구분하되, 각 비용은 한 번만 포함합니다. 요율 방식이면 적용 대상금액과 계산 근거를 첨부합니다. `세후총액 = 세전총액 + 확인된 부가세`이며 세율/적용 판단은 별도 확인합니다. 옵션과 제외공사 추정액은 기준안 총액에 자동 포함하지 않습니다.

부모행을 ‘타행포함’으로 처리하고 하위행을 합산하는 경우 포함 대상·집계 방식을 명시합니다. 같은 비용을 부모와 자식에 둘 다 적지 않습니다. 내부 JSON 기본형은 추가행을 허용하지만, 발주자 정본에 없는 항목은 검토 표시합니다.

## 5. 별도 표가 필요한 것

| 표 | 필수 필드 |
|---|---|
| 잠정금액 | PS-ID, 항목, 승인한 금액/단가·수량·범위, 설치 포함, 정산 기준, 승인 ADD-ID |
| 대안/옵션 | ALT-ID, 원안, 제안, 증감액, 사양·공기·설계 영향, 선택 여부 |
| 제외공사 | EX-ID, 위치/항목, 제외 이유, 별도 담당, 복구/연결 경계 |
| 지급품 | OS-ID, 제품, 수량, 구매·반입·설치·연결·보양·하자 주체 |
| 수량/설계 이견 | DEV-ID, 기준과 제안, 도면/산출 근거, RFI-ID, 미해결 비용 영향 |
| 비교보정 | ADJ-ID, 대상 항목, 비교범위 차이, 보정 근거·승인자, 세전 증감액 |

## 6. 업체별 비교 순서

**먼저 범위와 도서, 그 다음 사양·수량, 마지막 가격**을 비교합니다. 발행본·용도·수량방식·공통 답변 수신이 다르면 재확인합니다. 제외공사나 잠정금액을 맞추기 전 최저가 순위를 만들지 않습니다.

`비교용 세전금액 = 제출 기준안 세전총액 + 승인된 범위/사양 보정 증감액`입니다. 이 금액은 업체 계약금액이 아니라 내부 비교값입니다. 보정액은 객관적 견적/승인 근거가 있을 때만 입력하며, 모르는 차액은 임의 추정하지 않고 ‘비교 불가/보완 필요’로 둡니다. 가격·실제 팀·일정·품질·계약조건을 함께 검토합니다.

## 7. 현행 R1 회신과 이전 양식

**이번 사양에 대한 회신은 [R1 공통 양식](data/tender-response-template.json)을 사용합니다.** 단가/금액은 빈칸이지만 지정사양 참조와 일부 공통 비교수량·자재 기준단가는 이미 들어 있습니다. [시공사 사양서](TENDER.md)와 함께 사용합니다.

이전 [R0 양식](data/bid-template.json)과 [기본 스키마](data/bid-schema.json)는 과거 구조/계산 실험용으로 남겼습니다. 기존 `validate.py --bid`는 R0 구조 검사이며 R1을 검사하는 도구인 것처럼 사용하지 않습니다. `validate_tender.py`는 현행 사양·출처·범위연결·업체용 패키지의 일치 여부를 검사합니다.

실제 수신된 업체 견적은 비공개에 저장합니다. 자재 허용액은 본공사에 한 번만 포함하고 옵션은 별도입니다. 수량/사양/범위가 같아진 뒤 금액을 비교하며, 자동검사 통과가 공학적 설계나 계약조건 승인은 아닙니다.
